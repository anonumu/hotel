## 1. Главное о проекте за 1 минуту

- **Что это такое:** Информационная система управления гостиничным комплексом (**PMS — Property Management System**) с интерактивным поэтажным планом, модулем бронирования, службой приема гостей, учетом персонала, кассой и аналитикой.
- **Главный язык проекта:** **Java 21 / 17** (бэкенд написан полностью на Java).
- **Фреймворк:** **Spring Boot 2.7** (промышленный стандарт enterprise-разработки на Java).
- **База данных:** **H2 Database** (быстрая встроенная реляционная БД) с возможностью переключения на **PostgreSQL**.
- **Работа с данными:** **Spring Data JPA / Hibernate** (ORM — объектно-реляционное отображение).
- **Безопасность:** **Spring Security** (Basic Auth, разграничение ролей, CORS, защита от флуда и инъекций).
- **Сборщик:** **Apache Maven** (управляет зависимостями и сборкой JAR-файла).
- **Клиентская часть:** Одностраничный адаптивный веб-интерфейс (Single Page Application), который взаимодействует с Java-сервером через протокол **HTTP REST API (JSON)**.

## 2. Архитектура приложения (Трёхслойная архитектура / 3-Tier Architecture)

Весь Java-бэкенд спроектирован по классической трёхслойной архитектуре. Если преподаватель спросит: *«Какая у вас архитектура?»*, вы уверенно отвечаете:  
> *«Классическая трёхслойная архитектура: слой контроллеров (API), сервисный слой (бизнес-логика) и слой репозиториев (доступ к данным через JPA)»*.

```
   [Браузер / Фронтенд]
           │
           │ HTTP-запрос (GET / POST / PUT / DELETE) с телом в JSON
           ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. Слой контроллеров (Controller Layer)                     │
│    Классы с аннотацией @RestController                     │
│    Принимают запрос, валидируют параметры, вызывают сервис  │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. Сервисный слой (Service Layer)                           │
│    Классы с аннотацией @Service                             │
│    Вся бизнес-логика: проверка дат, расчет цен, статусы     │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. Слой репозиториев (Repository Layer)                     │
│    Интерфейсы, наследующие JpaRepository<Entity, Long>       │
│    Автоматическая генерация SQL-запросов через Hibernate     │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. База данных (H2 In-Memory Database)                      │
│    Таблицы: rooms, bookings, guests, staff, payments        │
└─────────────────────────────────────────────────────────────┘
```

### Подробно о каждом слое:

1. **Контроллеры (`com.hotel.controller`)** — диспетчеры.
   - Они не знают, как хранятся данные в базе. Их задача — слушать URL (например, `/api/v1/rooms`), принять от пользователя данные и передать их сервису.
   - Возвращают ответы в формате **JSON** со статусами HTTP (`200 OK`, `201 Created`, `400 Bad Request`, `404 Not Found`).

2. **Сервисы (`com.hotel.service`)** — мозг приложения.
   - Здесь находится вся бизнес-логика. Например:
     - Нельзя забронировать номер, если дата выезда раньше даты заезда.
     - Нельзя поселить 5 человек в двухместный номер.
     - Нельзя забронировать номер, который уже занят другим гостем на эти даты.
     - Расчет стоимости: `Количество_ночей * Цена_за_ночь`.

3. **Репозитории (`com.hotel.repository`)** — библиотекари.
   - Это интерфейсы, наследующие `JpaRepository`. Благодаря Spring Data JPA нам **не нужно писать SQL руками**.
   - Достаточно написать `roomRepository.findAll()` — и Spring сам сформирует SQL: `SELECT * FROM rooms;`.
   - `bookingRepository.save(booking)` — Spring сам сформирует: `INSERT INTO bookings ...`.

4. **Сущности / Модели (`com.hotel.model`)** — таблицы базы данных.
   - Обычные Java-классы с аннотацией `@Entity`, поля которых соответствуют колонкам таблицы в БД (`Room`, `Booking`, `Guest`, `Staff`, `Payment`, `Tariff`).

5. **DTO (`com.hotel.dto`) — Data Transfer Object**
   - Объекты для передачи данных между клиентом и сервером. Нужны для безопасности и валидации, чтобы клиент не мог напрямую перезаписать внутренние системные поля базы (например, дату создания записи).

## 3. База данных H2 и Hibernate: как сохраняются данные

Преподаватель может спросить: *«Где хранятся данные? Почему не PostgreSQL/MySQL?»*.

**Ваш ответ:**
> *«В качестве основной базы данных используется встроенная реляционная СУБД H2. Она работает прямо в памяти процесса Java и дублируется в локальный файл `hoteldb.mv.db`. Это позволяет запустить и протестировать проект на любом компьютере без установки и настройки отдельного сервера СУБД. При этом в проекте есть готовый профиль `application-postgres.properties` для мгновенного переключения на production-базу PostgreSQL простым изменением флага запуска»*.

### Как Hibernate сам создает таблицы:
В файле `application.properties` прописана строчка:
```properties
spring.jpa.hibernate.ddl-auto=update
```
Это означает: при старте приложения Hibernate сканирует все классы с аннотацией `@Entity` (`Room`, `Booking`, `Guest` и т.д.) и сам создает или обновляет таблицы в базе данных. Руками писать `CREATE TABLE` не требуется.

### Как зайти в веб-консоль H2:
1. Запустите проект (`http://localhost:8080/`).
2. Откройте в браузере: `http://localhost:8080/h2-console`.
3. Параметры подключения:
   - **JDBC URL:** `jdbc:h2:mem:hoteldb` (или `jdbc:h2:file:./hoteldb`)
   - **User Name:** `sa`
   - **Password:** *(оставить пустым)*
4. Нажмите **Connect**. Вы увидите все таблицы и сможете выполнять любые SQL-запросы прямо в браузере.

## 4. Главные аннотации Spring Boot (шпаргалка)

Если преподаватель ткнет пальцем в строчку кода и спросит: *«А что делает эта аннотация?»*, найдите её здесь:

| Аннотация | Где пишется | Что означает простыми словами |
| :--- | :--- | :--- |
| `@SpringBootApplication` | Над главным классом `HotelApplication` | Точка входа в программу. Включает автоконфигурацию Spring и сканирование всех компонентов. |
| `@RestController` | Над классом контроллера | Говорит Spring, что этот класс принимает веб-запросы, а все его методы возвращают готовые данные (JSON), а не HTML-страницы. |
| `@RequestMapping("/api/v1/...")` | Над классом контроллера | Задает общий базовый URL-адрес для всех методов этого контроллера. |
| `@GetMapping` | Над методом | Метод вызывается при HTTP-запросе **GET** (получение данных). |
| `@PostMapping` | Над методом | Метод вызывается при HTTP-запросе **POST** (создание новой записи). |
| `@PutMapping` | Над методом | Метод вызывается при HTTP-запросе **PUT** (полное обновление существующей записи). |
| `@DeleteMapping` | Над методом | Метод вызывается при HTTP-запросе **DELETE** (удаление записи). |
| `@PathVariable` | Перед аргументом метода | Извлекает значение из URL (например, из `/rooms/{id}` забирает число `id`). |
| `@RequestBody` | Перед аргументом метода | Берет JSON из тела запроса и превращает его в Java-объект (десериализация). |
| `@Service` | Над классом сервиса | Регистрирует класс как сервисный компонент бизнес-логики в контейнере Spring. |
| `@Repository` | Над интерфейсом репозитория | Регистрирует интерфейс для работы с базой данных. |
| `@Autowired` | Над конструктором или полем | **Внедрение зависимостей (Dependency Injection)**. Spring сам находит нужный объект и подставляет его сюда. |
| `@Entity` | Над классом модели | Указывает, что этот класс является таблицей в базе данных. |
| `@Table(name = "...")` | Над классом модели | Задает точное имя таблицы в базе данных (например, `rooms`, `bookings`). |
| `@Id` | Над полем `id` | Помечает поле как первичный ключ таблицы (**PRIMARY KEY**). |
| `@GeneratedValue` | Над полем `id` | Включает автоинкремент (база данных сама увеличивает ID: 1, 2, 3...). |
| `@Enumerated(EnumType.STRING)` | Над полем с enum | Сохраняет статус в БД в виде понятного текста (`AVAILABLE`), а не цифры. |
| `@Transactional` | Над методом сервиса | Транзакция. Если во время выполнения метода произойдет ошибка, все изменения в базе данных автоматически откатятся (Rollback). |
| `@Valid` | Перед `@RequestBody` | Включает автоматическую проверку правил валидации (например, `@NotNull`, `@Min`). |
| `@RestControllerAdvice` | Над классом `GlobalExceptionHandler` | Глобальный перехватчик ошибок для всех контроллеров. Если где-то падает исключение, этот класс перехватывает его и возвращает красивый JSON-ответ с описанием ошибки. |

## 5. Путь одного запроса: от клика мышки до строки в базе

Это любимый вопрос преподавателей: *«Покажите на примере, как проходит запрос от интерфейса до базы данных»*.

Возьмем пример: **Создание бронирования номера**.

1. **Пользователь в браузере:**
   - Нажимает кнопку «Создать бронь», выбирает номер 101, гостя, даты заезда `2026-11-20` и выезда `2026-11-25`, жмет «Подтвердить».
2. **JavaScript на клиенте (`hotel-frontend/js/bookings.js`):**
   - Собирает данные из формы в JSON-объект:
     ```json
     {
       "roomId": 1,
       "guestId": 1,
       "checkInDate": "2026-11-20",
       "checkOutDate": "2026-11-25",
       "guestCount": 2
     }
     ```
   - Отправляет HTTP-запрос через `fetch`:
     `POST http://localhost:8080/api/v1/bookings`
3. **Фильтр безопасности (`MutationRateLimitFilter.java`):**
   - Запрос попадает в фильтр на бэкенде. Фильтр проверяет: нет ли автоматического спама (не более 35 запросов за 2 секунды). Всё в порядке — запрос пропускается дальше.
4. **Контроллер (`BookingController.java`, метод `createBooking`):**
   - Аннотация `@PostMapping` перехватывает запрос.
   - Jackson десериализует JSON в объект `BookingRequestDto`.
   - Контроллер вызывает метод сервиса: `bookingService.createBooking(dto)`.
5. **Сервис (`BookingService.java`, метод `createBooking`):**
   - Проверяет корректность дат: дата выезда строго позже даты заезда.
   - Проверяет лимит гостей (от 1 до 10).
   - Находит номер в базе через `roomRepository.findById(dto.getRoomId())`.
   - Проверяет статус номера: номер не должен быть на ремонте (`OUT_OF_ORDER`).
   - Проверяет пересечения дат: через запрос `findOverlappingBookings` проверяет, нет ли уже активной брони на этот номер в эти даты.
   - Рассчитывает количество ночей (5 ночей) и умножает на тариф: `5 * 3500.00 = 17500.00 ₽`.
   - Создает объект `Booking` со статусом `CONFIRMED`.
   - Вызывает `bookingRepository.save(booking)`.
6. **Репозиторий и Hibernate (`BookingRepository.java`):**
   - Hibernate генерирует SQL-запрос:
     `INSERT INTO bookings (room_id, guest_id, check_in_date, check_out_date, total_price, status) VALUES (1, 1, '2026-11-20', '2026-11-25', 17500.00, 'CONFIRMED');`
   - Запись физически сохраняется в таблицу H2 Database.
7. **Ответ клиенту:**
   - Сервер возвращает HTTP статус `201 Created` с JSON созданной брони.
   - Фронтенд получает ответ, закрывает модальное окно, выводит зеленое уведомление «Бронирование успешно создано» и обновляет поэтажный план (номер меняет статус).

## 7. Безопасность и отказоустойчивость

Преподаватель часто спрашивает: *«Как защищена ваша система?»*.

Вы можете назвать **4 уровня защиты**, реализованных в проекте:
1. **Защита от SQL Injection:**
   - Благодаря использованию **Spring Data JPA / Hibernate**, все запросы к базе данных выполняются через параметризованные запросы (`PreparedStatement`). Внедрение стороннего SQL-кода через строки ввода технически невозможно.
2. **Защита от XSS и скриптовых инъекций (`SecuritySanitizer.java`):**
   - Текстовые поля проверяются регулярными выражениями на наличие тегов `<script>`, `onload=`, `javascript:` и опасных управляющих конструкций.
3. **Защита базы данных от флуда (`MutationRateLimitFilter.java`):**
   - Серверный фильтр отслеживает частоту запросов на изменение данных (POST, PUT, DELETE). Если скрипт попытается выполнить более 35 мутаций за 2 секунды, сервер вернет статус `429 Too Many Requests` и защитит пул соединений базы от исчерпания.
4. **Валидация диапазонов значений:**
   - В сервисах установлены жесткие бизнес-границы: количество гостей в одном номере (не более 10 человек), максимальная сумма разового платежа (не более 5 000 000 ₽), даты выезда строго после дат заезда.

## 8. ТОП-15 коварных вопросов преподавателя и готовые ответы

### 1. Почему выбран Spring Boot, а не обычная Java с сервлетами?
> **Ответ:** *«Spring Boot избавляет от написания огромного объема шаблонного кода (boilerplate). Он предоставляет встроенный сервер приложений Tomcat, автоматическую конфигурацию компонентов, удобное управление зависимостями через Maven и готовые механизмы для работы с базой данных (Spring Data JPA) и безопасностью (Spring Security). Это де-факто мировой стандарт разработки на Java»*.

### 2. Что такое Dependency Injection (DI) и где оно у вас используется?
> **Ответ:** *«Внедрение зависимостей (Dependency Injection) — это механизм, при котором объекты создаются и связываются между собой не вручную через оператор `new`, а автоматически контейнером Spring (IoC-контейнером). Например, в `BookingController` через конструктор внедряется `BookingService`, а в сервис внедряется `BookingRepository`. Это делает код модульным, легко тестируемым и снижает связанность компонентов»*.

### 3. Чем отличается `@RestController` от обычного `@Controller`?
> **Ответ:** *«Обычный `@Controller` используется в классических MVC-приложениях для возврата HTML-шаблонов (например, JSP или Thymeleaf). Аннотация `@RestController` — это комбинация `@Controller` и `@ResponseBody`. Она говорит о том, что методы контроллера возвращают не страницы, а чистые данные (сериализованные в JSON-формат) для нашего веб-клиента»*.

### 4. Что такое DTO и зачем они нужны, если есть `@Entity`?
> **Ответ:** *«DTO (Data Transfer Object) — это объект передачи данных. Мы разделяем сущности базы данных (`@Entity`) и DTO по соображениям безопасности и чистоты архитектуры. Сущность отражает структуру таблицы в БД, а DTO содержит только те поля, которые клиент имеет право передавать или видеть. Это защищает от атак типа Over-Posting / Mass Assignment, когда злоумышленник пытается перезаписать внутренние системные поля»*.

### 5. Как у вас реализован контроль занятости номеров при наложении дат?
> **Ответ:** *«В `BookingRepository` написан специальный JPQL-запрос `findOverlappingBookings`. Он ищет существующие подтвержденные брони на этот же номер, у которых дата начала меньше запрашиваемой даты окончания, а дата окончания больше запрашиваемой даты начала. Если список не пуст — сервис выбрасывает `BusinessLogicException` с сообщением о наложении дат»*.

### 6. Что делает аннотация `@Transactional`?
> **Ответ:** *«Она открывает транзакцию базы данных вокруг метода. Если все операции в методе завершились успешно, транзакция фиксируется (COMMIT). Если же в процессе выброшено исключение (например, не хватило средств или номер оказался занят), транзакция откатывается (ROLLBACK), и база данных возвращается в исходное состояние без частичных изменений»*.

### 7. Что такое CORS и зачем он настроен в `CorsConfig`?
> **Ответ:** *«CORS (Cross-Origin Resource Sharing) — это механизм браузера, который блокирует запросы между разными источниками (origin). Чтобы наш веб-интерфейс мог свободно обмениваться данными с сервером на порту 8080 (или при локальном открытии страницы), в `CorsConfig` прописаны разрешенные методы (`GET`, `POST`, `PUT`, `DELETE`) и заголовки»*.

### 8. Как работает централизованная обработка ошибок?
> **Ответ:** *«В пакете `com.hotel.exception` находится класс `GlobalExceptionHandler` с аннотацией `@RestControllerAdvice`. Методы с аннотацией `@ExceptionHandler` перехватывают специфические типы исключений (`ResourceNotFoundException`, `MethodArgumentNotValidException` и др.) и упаковывают понятный текст ошибки в единый формат `ErrorResponseDto` с нужным кодом статуса HTTP»*.

### 9. Как настроена аутентификация в Spring Security?
> **Ответ:** *«В классе `SecurityConfig` настроен `SecurityFilterChain`. Публичные статические файлы (`/`, `/index.html`, `/style.css`, `/js/**`), консоль H2 и публичные REST API разрешены для работы веб-интерфейса (`permitAll()`), а внутренние административные функции защищены с использованием `InMemoryUserDetailsManager` с ролями `ADMIN`, `MANAGER` и `RECEPTIONIST`»*.

### 10. Как база данных переводится в PostgreSQL?
> **Ответ:** *«В проекте уже подготовлен профиль `application-postgres.properties` с драйвером `org.postgresql.Driver`. Достаточно указать параметры хоста и базы данных в этом файле и запустить приложение с флагом `--spring.profiles.active=postgres`. Hibernate автоматически создаст все таблицы уже в PostgreSQL»*.

### 11. Что такое Enum и как он хранится в базе?
> **Ответ:** *«Enum — это перечисление строго ограниченного набора констант (например, типы номеров `STANDARD`, `SUITE`, статусы `AVAILABLE`, `BOOKED`). Над полями enum стоит аннотация `@Enumerated(EnumType.STRING)`, поэтому в БД они сохраняются в виде читаемых строк, а не числовых индексов (что защищает базу от повреждения при изменении порядка констант в коде)»*.

### 12. Как считается выручка и аналитика в `ReportService`?
> **Ответ:** *«Сервис `ReportService` агрегирует данные из репозиториев: суммирует проведенные платежи из `PaymentRepository`, группирует их по способам оплаты (карта, наличные, безналичный перевод) и рассчитывает процент загрузки фонда как отношение занятых номеров к общему количеству номеров»*.

### 13. Зачем нужен Maven?
> **Ответ:** *«Maven — это инструмент автоматизации сборки и управления зависимостями. Все внешние библиотеки (Spring Boot, Hibernate, драйвер H2, валидация) описаны в файле `pom.xml`. Команда `mvn clean package` компилирует Java-код, прогоняет модульные тесты и упаковывает весь проект в один исполняемый файл `hotel-backend-1.0.0.jar`»*.

### 14. Есть ли в проекте автоматические тесты?
> **Ответ:** *«Да, в папке `src/test/java` написаны модульные тесты с использованием JUnit 5 и Mockito (`RoomServiceTest`, `BookingServiceTest`, `SecuritySanitizerTest`), которые проверяют бизнес-логику номеров, расчет броней и работу санитайзера безопасности»*.

### 15. Как перезапустить демонстрационные данные, если кто-то удалил все номера?
> **Ответ:** *«В контроллере `SystemController` реализован метод `/api/v1/system/reset-demo`. Он в одной транзакции очищает таблицы и наполняет базу эталонным набором из 7 номеров на 4 этажах, гостей, броней и сотрудников. На фронтенде для этого есть специальная кнопка в шапке и баннер»*.
